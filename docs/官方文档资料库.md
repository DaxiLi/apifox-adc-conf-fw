### 1.2 ADC 配置文件结构（要点提炼，官方出处见 1.1）

按 [ADC Configuration Reference](https://github.com/api7/adc/blob/main/docs/reference/configuration.md)：

- 文件格式 **YAML 或 JSON** 均可；顶层只有 6 类资源键（全部可选）：

```yaml
services:         # 服务：内含路由(routes) + 上游(upstream)
consumers:        # 消费者：身份认证的用户
consumer_groups:  # 消费者组
global_rules:     # 全局规则（对象不是数组，键=插件名）
plugin_metadata:  # 插件元数据（键=插件名）
ssls:             # TLS 证书
```

- **重要语义：`adc sync` 是全量对账（reconciliation）**。命令作用域内、本地文件里没有的远端资源会被删除。
  要"只管理一部分"，用 `--include-resource-type` / `--exclude-resource-type` / `--label-selector` 圈定作用域
  （出处：[Configuration Reference 结构说明](https://github.com/api7/adc/blob/main/docs/reference/configuration.md)、[Label Selector 指南](https://github.com/api7/adc/blob/main/docs/guides/label-selector.md)）。
- 各资源必填字段（出处：[Configuration Reference · Schema Reference](https://github.com/api7/adc/blob/main/docs/reference/configuration.md)）：

| 资源 | 必填 | 其他常用字段 |
| ---- | ---- | ---- |
| service | `name`（唯一） | `description`、`labels`、`plugins`、`upstream`、`routes`、`path_prefix`、`strip_path_prefix` |
| route | `name`、`uris` | `hosts`、`methods`、`priority`、`plugins`、`enable_websocket`、`labels` |
| upstream | （`nodes` 与服务发现二选一） | `type`、`scheme`、`hash_on`、`key`、`timeout`、`checks`、`pass_host`、`retries`、`keepalive_pool` |
| consumer | `username`（唯一） | `labels`、`plugins`、`credentials[]` |
| credential | `name`、`type`、`config` | `type` ∈ `key-auth` / `basic-auth` / `jwt-auth` / `hmac-auth` |
| ssl | `snis`、`certificates` | `ssl_protocols`、`labels` |
| global_rules / plugin_metadata | 对象，键=插件名 | 值=插件配置/元数据 |

- 与 Admin API 的字段差异：ADC 用 `description`，APISIX Admin API 用 `desc`；ADC 的 `nodes` 是**数组**
  `[{host, port, weight, priority}]`，Admin API 是 `"host:port": weight` 键值对（本仓库 `official-site.yaml` 已按 ADC 数组写法）。

### 1.3 变量语法（三套，容易混）

出处：[ADC Configuration Reference · Variables](https://github.com/api7/adc/blob/main/docs/reference/configuration.md)（与归档版一致）：

| 语法 | 谁在何时解析 | 最低 ADC 版本 | 用途 |
| ---- | ---- | ---- | ---- |
| `$env://` | 数据面（网关节点）加载配置时 | v0.12.1 | 每台网关实例不同的值（懒加载、免重建） |
| `${ENV}` | ADC 读取配置文件时 | v0.12.0 | 外置密钥/环境相关值（推荐配合 `.env` 注入） |
| `\${}` | 数据面（网关）按请求求值 | v0.19.1 | APISIX 内置变量，如 `\${http_x_user_info.low_rate_limit}` |

注意：YAML 双引号字符串里要写成 `\\${...}`，单引号/裸值可直接写 `\${...}`。
想要字面量 `${VAR}` 不被 ADC 插值，用 `\${VAR}` 转义。

命令总览（出处：[CLI Command Reference](https://github.com/api7/adc/blob/main/docs/reference/cli.md)）：

```
adc ping      检查与后端的连通性
adc lint      本地校验（纯本地，不连后端）
adc validate  交给后端校验（不落地变更，适合 CI）
adc diff      本地 vs 后端差异（同时输出机器可读 diff.yaml）
adc sync      全量对账同步（create/update/delete）
adc dump      导出后端配置到本地文件
adc convert openapi   OpenAPI 2.0/3.x 转 ADC 配置
adc help      各命令帮助
```

> 官方推荐 CI 顺序：`lint → validate → diff → sync`（[Workflow Guide](https://github.com/api7/adc/blob/main/docs/guides/workflow.md)）。

### 2.3 多文件 / 多人协作 / 存量资源接管（重点指南）

| 指南 | 链接 | 状态 |
| ---- | ---- | ---- |
| **Resource IDs（ID 怎么生成、怎么接管存量资源）** | <https://github.com/api7/adc/blob/main/docs/guides/resource-ids.md> | ✅ 已验证 |
| **Label Selector（多团队/多流水线分区管理）** | <https://github.com/api7/adc/blob/main/docs/guides/label-selector.md> | ✅ 已验证 |

要点（出处同上）：
- 资源 ID 生成规则：`service = sha1(name)`、`route = sha1(service-name.route-name)`、`consumer = username`、`ssl = sha1(snis.join(','))` 等。
- 接管 UI/Admin API 创建的存量资源：先 `adc dump --with-id` 导出真实 ID，`adc diff` 无差异后再提交为基线；**不要删掉导出的 `id` 字段**，否则下次 sync 会把资源删了重建。
- 改名会改变生成的 ID（=删旧建新）；要保留 ID 需先导出 `id` 再改名。
- 多团队共用一台网关：给资源打标签 + `--label-selector team=xxx` 分区，防止互相误删。注意 `global_rules` / `plugin_metadata` 是全局的，不受 label 过滤。

### 2.4 OpenAPI 转换官方文档

| 文档 | 链接 | 状态 |
| ---- | ---- | ---- |
| **OpenAPI Converter Reference** | <https://github.com/api7/adc/blob/main/docs/reference/openapi-converter.md> | ✅ 已验证 |
| 归档版 | <https://docs.api7.ai/enterprise/reference/openapi-adc> | ⚠️ 归档版 |

要点（出处同上）：
- `adc convert openapi -f openapi.yaml -o adc.yaml`，支持 OpenAPI 2.0（Swagger）与 3.x。
- 用 `x-adc-*` 扩展控制生成的 service 名、route 名、插件、labels、upstream 默认值等：
  `x-adc-name`、`x-adc-labels`、`x-adc-plugins`、`x-adc-plugin-<name>`、`x-adc-service-defaults`、`x-adc-upstream-defaults`、`x-adc-upstream-node-defaults`、`x-adc-route-defaults`。
- 在 path/operation 级设置 `x-adc-service-defaults` 等会导致该路由被拆成独立 service。

## 5. 版本对应与升级

| 组件 | 本仓库版本 | 官方文档版本 | 说明 |
| ---- | ---- | ---- | ---- |
| ADC | `v0.30.3`（`.\adc.cmd --version`） | GitHub `main` 分支（文档随版本演进）；API7 归档文档 3.9.x | 变量语法 `$env://`/`${ENV}`/`\${}` 分别要求 ≥ v0.12.1 / v0.12.0 / v0.19.1，本版本全部支持 |
| Apache APISIX（后端） | 未在本仓库声明（远程网关） | 官网当前 3.18.0，可在文档右上角切换版本 | 插件参数以实际网关版本为准；可 `adc dump` 看后端实际接受字段 |

升级 ADC：从 <https://github.com/api7/adc/releases> 下载对应平台 zip，覆盖 `.bin\adc\adc.exe`。
升级后建议跑一次 `.\scripts\lint.ps1`（或 `.\adc.cmd lint -f configs/global/**/*.yaml -f configs/sites/**/*.yaml`）验证旧配置仍通过新 schema。
